# 验收工具使用边界

工具与原始实验数据分开管理。测试通过证明错误输入被拒绝，不代表 C1/C2/C3 验收通过。

## 判定

- C2：正整数样本对数、完整固定实验臂顺序、锁自身哈希、校准身份和阈值均须通过检查。作业失败、资源未归还、worker 来源缺失均无效。参数比较缺失时为 INCOMPLETE。
- Trace：从原始 gzip 重算，检查原始 SHA256 和 DP4 rank 0–3 的唯一完整覆盖；不能直接信任手写摘要。该工具专用于已有 DP4 冻结协议，不泛化到别的拓扑。
- 退出码：PASS 为 0；NOT_PASS/INCOMPLETE 为 1；INVALID 为 2。拒绝覆盖既有输出。
- C3：旧日志与文件增长无法关联到同一事件，延迟仍是 UNMEASURED，尾窗仍是 UNVERIFIED。

## 实验锁

新 runner 不接受缺少 EXECUTION 的旧锁。使用同一启动命令附加 `--freeze-execution NEW_LOCK.json`，只生成新锁，不连接 Ray、不创建作业；把新锁与预注册协议提交后，去掉此参数并将 `--lock` 指向新文件再运行。

冻结内容包括 recipe 实际哈希、输入哈希、产品版本、有效 recipe 参数、观察器配置、runner 哈希、启动环境哈希和实验臂顺序。环境值只参与哈希，不进入报告。任何漂移都拒绝运行，不自动续跑缺失实验臂。

启动环境哈希不是远程 worker 环境的完整证明；worker 源码来源仍需实测验证。新 recipe、拓扑、软件环境应重新预注册，不能修改旧协议使旧实验过关。

## 公开证据

`scan_public_evidence.py` 将日志及 gzip 解压内容交给 gitleaks stdin，避免 `.log` 路径排除导致漏扫；报告只保留规则、行号和哈希，不输出命中值。超限、非 UTF-8、扫描器失败均阻止发布。

`prepare_public_log.py` 仅将 RFC1918 地址替换为公开占位符；不改原文件。输出分别记录原始/公开件 SHA256，并要求所有提取的训练指标完全一致。转换完成仍须独立扫描，不能直接视为可发布。遇到密钥、内部域名或其他内容告警时，应单独处理，不自动删除整行训练记录。

本轮四臂日志脱敏后指标完全相同，独立扫描通过；原始文件未改写。原 trace 重算仍 NOT_PASS。GPU 新实验、跨进程事件延迟、逐参数数值比较不在这些 CPU 工具测试的通过范围内。
